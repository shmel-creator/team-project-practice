# Отчёт о практической работе

## Команда

Работа выполнена индивидуально. Все роли (координатор, разработчик 1,
разработчик 2, разработчик 3) выполнены одним студентом путём
последовательного переключения между задачами.

## Распределение ролей (имитация)

- Студент А: создание репозитория, настройка прав, защита main
- Студент Б: index.html
- Студент В: styles.css
- Студент Г: README.md

## Выполненные задачи

1. Создан репозиторий team-project-practice
2. Настроена защита ветки main (Require pull request, Require conversation
   resolution)
3. Созданы Issues #1, #2, #3
4. Реализованы файлы index.html, styles.css, README.md через отдельные
   ветки и Pull Requests
5. Проведено код-ревью с комментариями (по 2 комментария на каждый PR)
6. Разрешён конфликт слияния в README.md (версии Б и В объединены)
7. Настроен Project Board «Sprint 1» с автоматизацией
8. Проверена защита main: force-push отклонён (GH006 Protected branch)

## Возникшие сложности

- Невозможность одобрить собственный Pull Request.
  Решение: Require approvals = 0 в правилах защиты main.
- Конфликт в README.md при имитации параллельной работы.
  Решение: слияние main в ветку, ручное разрешение маркеров.
- Bypass защиты при прямом push (владелец репозитория может обойти правила).
  Решение: откат через PR #9.

## Выводы

Освоен полный цикл командной разработки в GitHub: создание репозитория,
защита ветки main, работа с Issues, Pull Requests, код-ревью,
разрешение конфликтов, Project Board.
